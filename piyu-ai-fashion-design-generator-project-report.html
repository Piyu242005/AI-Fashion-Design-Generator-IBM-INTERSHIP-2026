📋01 · Project Overview

The AI Clothing Fashion Design Generator is a three-stage generative AI pipeline that accepts a plain-English clothing description as input and produces a fully rendered, photorealistic virtual try-on image as output. It integrates three state-of-the-art AI models — RealVisXL, SAM, and IDM-VTON — into a coherent, scriptable, and web-accessible workflow.

The project targets fashion designers, AI/ML students, generative AI researchers, and anyone exploring virtual garment prototyping without physical samples. It runs on a GPU server or Google Colab, with all model weights managed centrally through Hugging Face and a dedicated model_manager.py download layer that eliminates any need to commit large binary files to the repository.

❓02 · Problem Statement

Traditional fashion design prototyping is expensive, slow, and requires physical fabric samples and live photoshoots. Online shoppers cannot visualise how a garment will look on a specific body type before purchase. Designers waste weeks iterating on physical prototypes before a concept is validated.

Core Challenge

How can anyone instantly visualise any garment on a photorealistic AI model — without a physical sample, photography session, or specialist 3D software?

This project solves the problem through a three-step AI pipeline: generate a photorealistic human model from a text prompt, segment the clothing region with SAM point-click precision, and apply any real garment image onto that region using SDXL-based diffusion inpainting.

Stage 1 — Human Model Generation · generate_model.py

Uses RealVisXL V4.0 Lightning via the auto1111sdk library. The user's clothing description is wrapped in a standardised portrait prompt template and passed to generate_txt2img(). Resolution: 768×1024 · Sampler: DPM++ SDE · Steps: 5 · CFG scale: 2.0. Model weight resolved via model_manager.get_realvisxl_path() — downloaded from Hugging Face on first use.

# Core generation call
MODEL_PATH = get_realvisxl_path()   # downloads from HF if not cached
pipe = StableDiffusionPipeline(MODEL_PATH, default_command_args='--device-id 0')

image = pipe.generate_txt2img(
    prompt   = f"portrait photo of a woman, wearing {clothing_type}, natural skin, dark shot",
    negative_prompt = "(worst quality, low quality, blurry:1.2), (bad anatomy:1.1) ...",
    height=1024, width=768, cfg_scale=2, steps=5, sampler_name='DPM++ SDE'
)

Stage 2 — Clothing Segmentation · segment.py

Loads SAM ViT-H onto CUDA. Accepts three positive point prompts identifying the clothing region. Runs a two-pass prediction: Pass 1 — multimask_output=True to select the best logit by confidence score; Pass 2 — multimask_output=False with that logit as mask_input for a refined single mask. Saved as *_mask.jpg. Supports interactive GUI (local) and headless --points x1,y1,x2,y2,x3,y3 (Streamlit / Colab / server).

# Two-pass SAM prediction
predictor.set_image(image_rgb)
masks, scores, logits = predictor.predict(
    point_coords=input_point, point_labels=input_label, multimask_output=True
)
mask_input = logits[np.argmax(scores), :, :]   # best logit

masks, _, _ = predictor.predict(
    point_coords=input_point, point_labels=input_label,
    mask_input=mask_input[None, :, :], multimask_output=False
)                                                   # refined single mask

Stage 3 — Virtual Try-On · try_on.py

Loads the full IDM-VTON pipeline from yisol/idm_vton on Hugging Face. Dual-UNet architecture: a main denoising UNet + a dedicated garment-encoder UNet. Also loads two CLIP text encoders, one CLIP vision encoder, SDXL VAE, DDPMScheduler. Supporting models: DensePose R-50 FPN (Detectron2) for body pose estimation; ATR and LIP ONNX models for human parsing. Inference: 30 DDPM steps, guidance_scale=2.0, strength=1.0, float16, seed-controlled.

# Simplified IDM-VTON inference call
images = pipe(
    prompt_embeds             = prompt_embeds.to(device, torch.float16),
    negative_prompt_embeds    = neg_embeds.to(device, torch.float16),
    num_inference_steps       = 30,
    strength                  = 1.0,
    pose_img                  = pose_tensor,       # DensePose output
    text_embeds_cloth         = prompt_embeds_c,   # garment description
    cloth                     = garm_tensor,        # garment image tensor
    mask_image                = mask,               # SAM Stage 2 mask
    image                     = human_img,          # Stage 1 reference image
    height=1024, width=768, guidance_scale=2.0,
    ip_adapter_image          = garm_img,           # IP-Adapter garment conditioning
)[0]

✨06 · Key Features

Text-to-Fashion-Model Generation

RealVisXL V4.0 Lightning generates a 768×1024 photorealistic portrait from a plain-English clothing description in just 5 DPM++ SDE denoising steps — fast enough for interactive iteration.

Dual-Mode Segmentation (Interactive + Headless)

Interactive Matplotlib GUI for local desktop use. Headless --points x1,y1,x2,y2,x3,y3 CLI flag for Streamlit, Colab, and servers. Both paths use identical SAM ViT-H two-pass logic.

SDXL Virtual Try-On with DensePose + IP-Adapter Conditioning

IDM-VTON composites a garment image into the masked clothing region over 30 DDPM denoising steps, conditioned on DensePose body geometry, dual CLIP text embeddings, and IP-Adapter garment features.

Hugging Face Model Manager (model_manager.py)

Clean download-and-cache layer via hf_hub_download(). All ~25 GB of weights cached in models/ after first download. Zero weights committed to the repository. Configurable via HF_REPO_ID and MODEL_DIR env vars.

Streamlit Web UI — Two Pipeline Modes

Generate & Try-On: Full pipeline from text prompt to result with six-step pipeline progress strip. Try-On Only: Upload person photo + garment, skip generation stage. All models cached with @st.cache_resource — loaded once per server process.

Premium Dark-Tech UI Design System

Full CSS design system injected via st.markdown(unsafe_allow_html=True): Inter font, dark palette (#0a0d14 base), glassmorphism section cards with coloured step badges, animated GIF hero, blue-to-indigo gradient action buttons, sticky output panel with empty-state illustration.

⚙️08 · Installation Guide

Step 1 — Clone the repository

git clone https://github.com/Piyu242005/Piyu-AI-clothing-fashion-design-generator.git
cd Piyu-AI-clothing-fashion-design-generator

Step 2 — Create a virtual environment

# Linux / macOS
python3 -m venv venv && source venv/bin/activate
# Windows PowerShell
python -m venv venv; .\venv\Scripts\activate

Step 3 — Install PyTorch with CUDA wheel

pip install torch==2.1.0 torchvision --index-url https://download.pytorch.org/whl/cu118

Step 4 — Install all Python dependencies

pip install --upgrade pip
pip install -r requirements.txt

Step 5 — Install source-only dependencies

pip install 'git+https://github.com/facebookresearch/detectron2.git'
pip install 'git+https://github.com/facebookresearch/segment-anything.git'

Step 6 — Clone IDM-VTON and place try_on.py

git clone https://github.com/yisol/IDM-VTON.git idm_vton
cp try_on.py idm_vton/
# try_on.py uses relative imports (src/, utils_mask, apply_net)
# and must run from inside idm_vton/

Step 7 — Set up environment variables

cp .env.example .env
# Open .env and set:
# HF_TOKEN=hf_your_token_here
# HF_REPO_ID=Piyu242005/piyu-fashion-models

Step 8 — Launch the Streamlit app

streamlit run app.py
# On first run: model_manager.py downloads ~25 GB of weights from HF
# Subsequent runs use the cached models/ directory
First-Run Download Notice

model_manager.py downloads all required weights from Hugging Face on first run (~25 GB total). Ensure sufficient disk space and a stable internet connection. Subsequent runs skip the download and load from the local models/ cache.

Two Pipeline Modes

Mode 1 — Generate & Try-On

Text prompt → click ⚡ Generate Model → RealVisXL creates figure (pipeline step 2 set) → inspect image, note pixel coords → upload garment → click ✨ Apply Garment → SAM segments (step 3) + IDM-VTON composites (step 5) → result displayed + ⬇ Download PNG button.

Mode 2 — Try-On Only

Upload person photo + garment image (inline previews shown) → enter cloth type description + three pixel coordinates → click ✨ Apply Garment → SAM + IDM-VTON → result displayed + ⬇ Download PNG button.

🗺️12 · Limitations & Future Roadmap

Known Limitations

LimitationDetail
GPU requiredAll three stages run on CUDA. CPU fallback exists in code but is not practical for these model sizes.
VRAM pressureIDM-VTON dual-UNet SDXL at float16 requires ~16 GB VRAM. Run stages as separate processes to avoid accumulation.
Manual segmentationCoordinate-based input requires visual inspection of the image. Incorrect coordinates yield poor masks and degrade try-on quality.
Fixed resolutionPipeline is hardcoded to 768×1024. Other resolutions require script modification.
IDM-VTON directory dependencytry_on.py uses relative imports (src/, utils_mask, apply_net) and must run from inside idm_vton/, complicating Streamlit integration.
Non-commercial licenseIDM-VTON checkpoints are CC BY-NC-SA 4.0. Commercial deployment is not permitted without contacting the original authors.
Colab session limits~25 GB of weights are lost on session disconnect. Re-download required unless weights are stored on Google Drive.
Single garment per runThe pipeline applies one garment at a time. Multi-garment workflows require multiple sequential runs.

Project Summary & Conclusion

The Piyu AI Clothing Fashion Design Generator demonstrates a complete, deployable, end-to-end generative AI pipeline for virtual fashion prototyping. It integrates three leading open-source AI models — RealVisXL V4.0 Lightning, Segment Anything ViT-H, and IDM-VTON SDXL — into a coherent system with a professional Streamlit web interface, cloud model storage via Hugging Face Hub, and a clean Python codebase designed for reproducibility and extensibility.

The project demonstrates practical skills across the full ML engineering stack: multi-model integration, weight management via hf_hub_download, GPU inference optimisation (float16, VRAM-aware staged loading), headless/server-compatible pipeline design, premium web UI development with custom CSS design systems, cloud deployment architecture, and open-source best practices including license compliance, .gitignore hygiene, and .env secrets management.

It is production-ready for non-commercial demonstration, portfolio presentation, and internship evaluation — and provides a solid technical foundation for the planned roadmap toward a fully automatic, commercially-viable virtual try-on product.
